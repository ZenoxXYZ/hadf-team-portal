# HADF Portal Visual / Component System

## Visual language
- **Blue** — concepts, architecture, contracts
- **Green** — verified, safe, complete
- **Amber** — decisions, caution, freezes
- **Red** — blocked, P0, danger, recovery
- **Purple** — agent workflow
- **Gray** — supporting / reference information

## Major components
- Sticky desktop sidebar + mobile drawer navigation
- Learn/Event mode switch
- 4-member / 3-member team-size switch
- Landing identity model: framework / repository / stack / agents / humans
- Learning phase accordions with local progress controls
- Clickable full-stack flow with evidence/failure/owner detail panel
- Stack rationale cards
- Transaction/concurrency/idempotency visual blocks
- QA testing ladder + full-stack debugging boundary flow
- Clickable repository artifact cards + copy templates
- Comparison cards for fundamental distinctions
- Role tabs with deep operating manual content
- Agent workflow diagram + stop rule
- Workstream state machine
- Backend/frontend rendezvous visualization + completion-time tabs
- Git/migration runbook cards
- 24-hour timeline
- First-three-hours command cards
- RapidRelief case-study accordions
- Recovery playbook cards
- Final-four-hour war-room cards
- Filterable prompt library with Copy + Expand/Collapse
- Copy-ready repository templates and handoff packets
- Persistent interactive checklists
- Searchable glossary
- Full 146-page source reference
- Global search overlay

## Progressive disclosure model
Short explanation → expandable detail / role or runbook → source reference. The default interface is not a PDF text dump, while the full source remains accessible and searchable.

## Responsiveness
Desktop uses persistent navigation; tablet collapses grids; phone uses sticky top bar and drawer. Tables are avoided where cards are more readable; horizontal process flows are scrollable.
