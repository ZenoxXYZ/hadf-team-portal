Part V

Transactions

All related state changes either commit together or roll back together.

BEGIN→validate→change A→change B→record→COMMIT
failure→ROLLBACK

Concurrency

Correctness must still hold when two actors attempt the same limited-state operation at nearly the same time.

User AInvariant
resource cannot be overallocatedUser B

Idempotency

A retry with the same logical request identity must not create a duplicate side effect.

Request K→execute once→result
Retry K→same logical result→no duplicate
HADF rule: identify the invariant first. Row locks, optimistic concurrency, uniqueness constraints and isolation levels are implementation mechanisms chosen to protect that invariant.

AGENT STOP RULE

If implementation requires changing shared architecture, public API contract, shared schema, business invariant, major dependency, MVP, Golden Path, or another person's owned workstream, the Builder must stop and escalate.
